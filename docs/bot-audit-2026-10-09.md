# Bot audit and improvements — October 9, 2026

The audit focused on setup, player help, guided report review, staff report updates, Discord interaction failures, attachment handling, and status presentation. Existing connected-service, identity, permission, and dashboard tests were included in regression validation. This is a source and local behavior audit; it does not verify the live Discord server, Kinetic configuration, website deployment, Minecraft server, or Ollama inference.

## Findings fixed

| Finding | Result |
| --- | --- |
| Setup panel choices all ran the same full check | Each section now checks its own area; staff can use `/setup` directly |
| Setup fields were truncated and the staff log check was absent from displayed groups | Every finding is displayed, with additional private messages when needed |
| A configured text channel could pass as a forum; target permissions were not checked | Checks verify server membership, channel type, effective target permissions, and forum tags |
| Optional playtest settings looked like core failures | Optional unconfigured features are marked OFF |
| Some panel, private channel, and modal flows waited for network work before responding | These flows acknowledge the interaction before external work |
| Old review controls could submit while a player was answering or race another submission | Controls check the current review state and lock submission before awaiting Discord |
| A confirmation failure after storage could reopen the form and create duplicates | Saved report IDs fence the completed submission and direct staff to the stored report |
| Discord delivery failure could turn a stored report into a generic submission error | Delivery returns an explicit not-posted result; receipts say the report is saved and provide recovery guidance |
| Add information used text-channel fallbacks even when the original category used a forum | Updates use the configured report destination and forum tags |
| Unknown/retired components could produce no response | Unrecognized components offer a private route back to `/help` |
| Deferred reply errors could leave the loading message hanging; a deferred button-update error could clear a shared card | Reply errors finish the private reply; deferred component-update errors use a private follow-up |
| Attachment limits were checked after buffering the entire response | Downloads validate the Discord HTTPS host, reject redirects, retain a timeout, and stop streaming at the byte limit |
| Long review, bug, known-issue, and staff search cards could exceed Discord limits | Display text fits the aggregate embed budget while saved report details remain intact |
| Info cards and the shared footer claimed systems were online without observations | Help, panels, and `/status` share observed status; the footer identifies the community support bot |
| Help cards repeated many commands and lacked direct entry buttons | `/help` offers Report bug, Crash help, Ask staff, Privacy, and Server status buttons; the public hub uses compact guidance groups |
| Setup instructions missed the intent needed for guided report answers | The setup guide, README, and environment example explain Message Content Intent and first-run diagnostics |

Player messages now use clearer Wilderness Odyssey branding, explain private intake versus public archive posts, show report IDs, and distinguish saving from posting. Existing command names, stored records, database paths, credential names, dashboard authorization, and hosting startup configuration remain compatible.

## Validation

The original suite passed 75 tests before changes. The final suite passed 94 tests on **Node.js 22.13.1**, including 19 new regression tests for setup section isolation, setup acknowledgments, wrong channel types, Q&A reply permissions, long diagnostics, staff authorization, observed status, delivery failure, oversized/untrusted attachments, stale/concurrent review controls, saved-report receipt failure, forum updates, retired components, shared-card error handling, and embed limits.

The repository TypeScript checks, production build, and `git diff --check` passed. Discord interactions in the new tests use controlled API doubles; the tests do not log in or register commands. SQLite's experimental warning is expected on this Node release.

## Remaining improvements

1. **Resume unfinished drafts after restart.** Guided intake is held in a bounded in-memory cache with a one-hour expiry. The updated introduction states the limit. Persisting drafts would need explicit retention and restart behavior.
2. **Deliver saved reports after a temporary Discord outage.** Reports survive failed delivery and staff can find them by ID, but there is no durable retry queue for these community archive posts. Any future queue should reuse existing bounded outbox patterns and avoid duplicate posts after ambiguous Discord responses.
3. **Limit repeated private channel creation.** The intake cache is bounded, but players can open multiple private intake channels. Reusing an active channel and applying a per-player creation limit would reduce clutter and hosting/Discord pressure.
4. **Improve ticket closure when DMs are disabled.** The existing closure flow preserves the channel if the owner cannot receive the transcript. A future authenticated transcript retrieval path could allow closure while preserving access to the transcript.
5. **Expand role and deployment diagnostics.** `/setup` checks role configuration presence, channels, tags, and permissions. It does not prove that role IDs are valid, compare deployed commands, inspect the Developer Portal intent toggle, or test real connected-service credentials.

These are recorded follow-up improvements, not completed functionality. There is no automatic deletion of ticket history or destructive data migration in this change.

## Rollout and live acceptance

Build and upload through the existing hosting process, run `npm run deploy` to register the added `/setup` command, and replace existing public panel messages if you want the new wording. Then verify `/setup` as staff, denied player access, `/help` buttons, a private report with review/edit/submit, a suggestion vote, a report update in a forum, and status with both available and missing telemetry. Check actual channel/role permissions, disabled DMs, and a deliberately unavailable report destination in a test server before relying on the new behavior in production.

The bot was not deployed, logged into Discord, or connected to production services during this audit. Changes are left uncommitted for review.

## Reference constraints

Discord requires an initial response within three seconds, so slow operations acknowledge first. See [Discord interaction responses](https://github.com/discord/discord-api-docs/blob/main/developers/interactions/receiving-and-responding.mdx).

Forum creation uses Send Messages and replies use Send Messages in Threads; the target permissions differ from those of the panel channel. See [Discord thread permissions](https://github.com/discord/discord-api-docs/blob/main/developers/topics/threads.mdx).

Discord limits total embed text to 6,000 characters. See [Discord message and embed limits](https://github.com/discord/discord-api-docs/blob/main/developers/resources/message.mdx).
